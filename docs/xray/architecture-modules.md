## 🔄 核心业务流程

### 1️⃣ 快速部署流程 (VLESS + Reality)

```
用户输入
    ↓
┌─────────────────────────────────────────┐
│ 域名优选模块 (domain.sh)                │
│ • 测试20+个知名域名的TLS握手延迟        │
│ • 按延迟排序,推荐最优域名               │
│ • 用户选择或使用默认域名                │
└─────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────┐
│ 节点管理模块 (node.sh)                  │
│ • 生成Reality密钥对(privateKey/publicKey)│
│ • 创建节点配置                           │
│   - 端口: 443                            │
│   - 协议: VLESS                          │
│   - 传输: TCP                            │
│   - 安全: Reality                        │
│   - Flow: xtls-rprx-vision               │
│ • 保存到 nodes.json                      │
└─────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────┐
│ 绑定管理模块 (user_node_binding.sh)     │
│ • 绑定 admin 用户到新建节点              │
│ • 保存绑定关系到 node_users.json        │
└─────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────┐
│ 配置生成器 (config_generator.sh)        │
│ • 读取 nodes.json、users.json            │
│ • 读取 node_users.json 获取绑定关系     │
│ • 生成 inbound 配置:                     │
│   - clients: admin用户的UUID             │
│   - streamSettings: TCP配置              │
│   - realitySettings: Reality参数         │
│ • 生成完整 config.json                   │
│ • 原子性写入文件                         │
└─────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────┐
│ 内核管理模块 (core.sh)                  │
│ • 重启 Xray 服务                         │
│ • 应用新配置                             │
└─────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────┐
│ 节点管理模块 (node.sh)                  │
│ • 生成 VLESS 分享链接                    │
│ • 显示二维码                             │
│ • 显示手动配置参数                       │
└─────────────────────────────────────────┘
    ↓
完成部署 ✅
```

### 3️⃣ 配置生成流程 (核心逻辑)

```
触发条件:
• 添加/删除节点
• 添加/删除用户
• 修改绑定关系
• 修改用户状态
    ↓
┌──────────────────────────────────────────┐
│ 配置生成器 (config_generator.sh)         │
│ generate_xray_config()                   │
└──────────────────────────────────────────┘
    ↓
┌──────────────────────────────────────────┐
│ 第一阶段: 读取数据源                     │
│ • 读取 nodes.json → 获取所有节点配置     │
│ • 读取 users.json → 获取所有用户信息     │
│ • 读取 node_users.json → 获取绑定关系    │
│ • 读取 outbounds.json → 获取出站规则     │
└──────────────────────────────────────────┘
    ↓
┌──────────────────────────────────────────┐
│ 第二阶段: 遍历节点生成 inbounds          │
│                                          │
│ for each node in nodes.json:            │
│   ├─ 获取节点基础信息                    │
│   │  • port (端口)                       │
│   │  • protocol (VLESS/VMess/Trojan/SS) │
│   │  • transport (TCP/WS/gRPC/mKCP)     │
│   │  • security (Reality/TLS/None)      │
│   │                                      │
│   ├─ 查询绑定用户                        │
│   │  • 从 node_users.json 查找           │
│   │    port={当前端口} 的 users数组      │
│   │  • 获取 UUID 列表                    │
│   │                                      │
│   ├─ 生成 clients 配置                   │
│   │  • 遍历 UUID 列表                    │
│   │  • 从 users.json 查询用户详情        │
│   │  • 过滤 enabled=false 的用户         │
│   │  • 根据协议生成客户端配置:           │
│   │    - VLESS: {id, email, level, flow?}│
│   │    - VMess: {id, email, level}       │
│   │    - Trojan: {password, email, level}│
│   │    - SS: {password, email, level}    │
│   │                                      │
│   ├─ 生成 streamSettings 配置            │
│   │  • TCP: tcpSettings                  │
│   │  • WebSocket: wsSettings (path)     │
│   │  • gRPC: grpcSettings (serviceName)  │
│   │  • mKCP: kcpSettings (seed)          │
│   │                                      │
│   ├─ 生成 security 配置                  │
│   │  • Reality:                          │
│   │    - dest, serverNames               │
│   │    - privateKey, shortIds            │
│   │  • TLS:                              │
│   │    - certificates (certFile, keyFile)│
│   │    - alpn                             │
│   │  • None: 无配置                      │
│   │                                      │
│   └─ 组装 inbound 对象                   │
│      {                                   │
│        "tag": "vless-443",               │
│        "port": 443,                      │
│        "protocol": "vless",              │
│        "settings": { clients: [...] },   │
│        "streamSettings": {...},          │
│        "sniffing": {                     │
│          "enabled": true,                │
│          "destOverride": ["http","tls"]  │
│        }                                 │
│      }                                   │
└──────────────────────────────────────────┘
    ↓
┌──────────────────────────────────────────┐
│ 第三阶段: 生成 outbounds 配置            │
│                                          │
│ 固定出站:                                │
│ ├─ direct (自由出站, 直连)               │
│ ├─ block (黑洞出站, 拦截)                │
│ └─ api (API管理出站)                     │
│                                          │
│ 自定义出站:                              │
│ • 从 outbounds.json 读取规则库           │
│ • 如果节点配置了 outbound_tag            │
│ • 则添加对应的上游代理配置               │
└──────────────────────────────────────────┘
    ↓
┌──────────────────────────────────────────┐
│ 第四阶段: 生成 routing 配置              │
│                                          │
│ routing: {                               │
│   rules: [                               │
│     {                                    │
│       "type": "field",                   │
│       "ip": ["geoip:private"],           │
│       "outboundTag": "block"             │
│     },                                   │
│     {                                    │
│       "type": "field",                   │
│       "ip": ["geoip:cn"],                │
│       "outboundTag": "direct"            │
│     },                                   │
│     {                                    │
│       "type": "field",                   │
│       "domain": ["geosite:cn"],          │
│       "outboundTag": "direct"            │
│     }                                    │
│   ]                                      │
│ }                                        │
└──────────────────────────────────────────┘
    ↓
┌──────────────────────────────────────────┐
│ 第五阶段: 生成 API/Stats 配置            │
│                                          │
│ api: {                                   │

    ↓

│   "api": {...},                          │

└──────────────────────────────────────────┘
    ↓
┌──────────────────────────────────────────┐
```

## 📈 性能优化机制

### 1. 模块化加载
```
xray-manager.sh 启动
    ↓
优先加载核心模块:
├─ common.sh          (日志、工具)
├─ input-validation.sh (验证基础)
└─ safe_json.sh       (数据安全)
    ↓
按需加载业务模块:
只加载用户当前需要的功能模块
避免一次性加载所有模块
```

### 2. JSON 操作优化
```
高效读取:
• jq 高性能查询
• 缓存常用数据(用户列表、节点列表)
• 避免重复解析

安全写入:
• 原子性操作(tmp + mv)
• 批量修改合并为单次写入
• 写入后验证
```

### 3. API 动态管理
```
用户启用/禁用:
传统方式: 修改config.json → 重启Xray (中断连接)
API方式:  调用xray_api.sh → 动态添加/删除用户 (无需重启)

优势:
• 零停机时间
• 不影响现有连接
• 实时生效
```

## 🎨 架构设计亮点

### ✅ 分离式架构
```
传统架构:
节点配置 = 固定用户列表
• 修改用户需重建节点
• 一个用户只能用一个节点

S-Xray架构:
节点配置 + 用户池 + 绑定关系
• 用户与节点解耦
• 灵活绑定(一对多、多对多)
• 便于管理和扩展
```

### ✅ 三层协议架构
```
协议层: VLESS / VMess / Trojan / SS
    ↓
传输层: TCP / WebSocket / gRPC / mKCP
    ↓
加密层: Reality / TLS / None

灵活组合示例:
• VLESS + TCP + Reality      (推荐配置)
• VMess + WebSocket + TLS    (伪装流量)
• Trojan + gRPC + TLS        (高性能)
• SS + TCP + None            (简单部署)
```

### ✅ 配置生成器模式
```
好处:
• 数据与配置分离
• 配置自动生成,减少人为错误
• 易于备份和恢复
• 支持配置模板化

流程:
JSON数据 → config_generator.sh → config.json → Xray运行
```

### ✅ 订阅系统设计
```
多格式支持:
• Base64:  通用格式,广泛兼容
• Clash:   YAML格式,适合路由规则
• SingBox: JSON格式,新一代客户端

元数据管理:
• 流量限制
• 有效期
• 订阅更新时间
• 订阅URL管理
```

## 🎯 总结

S-Xray采用**分层模块化架构**:

1. **用户交互层**: 主菜单系统,提供10个功能模块入口
2. **业务逻辑层**: 18个功能模块,职责清晰,相互协作
3. **基础设施层**: 公共库、验证、安全等基础服务
4. **数据存储层**: JSON文件存储,数据与配置分离
5. **服务层**: Xray-Core核心服务

核心设计理念:
- ✅ **分离**: 用户与节点分离、数据与配置分离
- ✅ **安全**: 多层验证、原子操作、日志审计
- ✅ **灵活**: 三层协议架构、灵活绑定关系
- ✅ **高效**: 模块化加载、API动态管理、JSON优化
- ✅ **易用**: 一键部署、智能优选、多格式订阅
